## 1. Executive Summary & Architectural Reality Check

The repository contains substantial domain engineering (HarfBuzz Devanagari shaping, ReportLab magazine layout, SHA-256 publication idempotency, Static GK lookup tables, and 902 passing offline tests locally). However, it currently suffers from **architectural split-brain, fail-open quality gates, disconnected verification modules, key-pool rotation defects, and CI/workflow drift** that prevent reliable autonomous operation:

1. **Three Competing Implementations (`main.py` + `agents/` + `pipeline/` vs `enterprise_v2/` vs `pipeline/collector.py` / legacy agent blocks):**
   - `14 of 15` modules in `enterprise_v2/` are **dead shadow clones** unused by `main.py` or production workflows; only `enterprise_v2/store.py` is imported by `agents/25_auto_healer.py` (making `auto-heal.yml` test and log against phantom state files `state/api_health.json` / `state/feed_health.json`).
   - High-value safety modules (`pipeline/claim_verifier.py`, `pipeline/gnews.py`, `pipeline/story_registry.py`, `pipeline/verify.py`, `config/registry.py`, `config/branding.py`, `config/news_sources.json`) exist on disk and pass unit tests in isolation, yet are **never invoked** by `main.py` or the active production stages.
2. **Broken Key-Pool Rotation & Quota Exhaustion (`pipeline/ai_router.py`):**
   - Pooled keys (`GEMINI_API_KEY_1..7`, `GROQ_API_KEY_1..2`) are ignored completely if the unnumbered base key (`GEMINI_API_KEY` / `GROQ_API_KEY`) is absent.
   - `Provider.rotate_key()` wraps infinitely (`(key_idx + 1) % len(key_pool)`) and unconditionally calls `_clear_provider_quota_state()`, wiping model blocks/RPD counters and preventing cooled-down providers from resting (producing **657 `rate_limit` failures vs 346 successes** for Groq in `logs/ai_usage.jsonl` on `2026-11-22`).
   - `daily.yml` omits `logs/ai_health/` from `pipeline-checkpoints` artifact uploads, so every overnight cron wave starts fresh and forgets RPD counts, `402` bans, and rotated key indices.
   - `OPENAI_API_KEY` / `OPENAI_API_KEY_1` were removed in commit `712a6e4` and explicitly blocked by `tests/test_all_keys.py`; owner's two OpenAI keys currently have no safe adapter or zero-token healthcheck path.
   - Observability files `logs/provider_health.json` and `logs/provider_summary.json` do not exist; `logs/ai_usage.jsonl` lacks `key_slot`, token counts, latency, and cost, and is polluted by `pytest` runs because `tests/conftest.py` does not isolate `ALP_AI_USAGE_LOG`.
3. **Critical Fail-Open Content, Fact-Checking & MCQ Gaps:**
   - **Stage 04 (`agents/04_fact_verification.py`):** Any Tier 1/2 outlet (`is_curated_editorial`) passes automatically with zero independent corroboration (`base = 0.58 >= 0.45`), `publisher` fallback allows undecoded `news.google.com` links to impersonate official primary sources, syndicated wire copy (PTI/ANI/IANS) counts as multiple independent sources, and claim-level verification (`pipeline/claim_verifier.py`) is never executed.
   - **Hindi & Editorial (`pipeline/content.py`, `ai_translator.py`, `hindi_postfix.py`, `content_sanitizer.py`):** Batch headlines bypass `ai_translator._validate()`, English polish runs *after* Hindi headline translation, `_CAPS_WORD_HI` misspells WHO as `विस्व`, `LEFTOVER_WORD_HI` is unindexed, `content_sanitizer.py` chops valid words ending in `में`/`को`, and `config/current_facts.json` has 4 entries with empty `name_hi`.
   - **MCQs (`agents/16`, `17`, `pipeline/content.py`, `mcq_builder.py`, `mcq_schema.py`):** `_qkey()` 60-character truncation causes every `state_mcq` and `country_mcq` to hash identically; `generate_llm_mcqs()` passes `needs_hindi=False`; `_in_text()` allows substring collisions (`"10"` in `"102"`, `"UN"` in `"unit"`); Stage 17 only re-runs Stage 16's schema/regex validator with **less** coverage (`hindi_errors` & `_org_grounded` missing) and no independent semantic examiner.
4. **QA Blind Spots & Release Gate Limitations (`agents/19_pdf_qa.py`, `22_telegram_publisher.py`):**
   - `PDF_QA_RENDER_CHECK` (`19_pdf_qa.py:168`) is dead code: `19_pdf_qa.py` **never renders pages visually**, treats `"poppins"` as proof of Devanagari font support (`check_fonts:558`), masks missing real photos using HarfBuzz PNG XObjects (`check_images:922`), lets `>70%` blank pages pass because header/watermark satisfy `detect_blank_pages()`, and leaves `PDF_QA_STRICT=0` in production workflows so warnings publish by default.
   - `22_telegram_publisher.py` hashes PDFs properly inside `main.py`, but skips checkpoint chain verification when run standalone without `ALP_JOB_ID`, and stamps weekly/monthly captions as `"Daily Current Affairs"`.
5. **Weekly & Monthly Failures + CI Breakage:**
   - `auto-heal.yml` listens for `"Weekly News Pipeline"` / `"Monthly News Pipeline"`, whereas actual workflow names are `"Weekly Current Affairs"` / `"Monthly Current Affairs"`.
   - `weekly.yml` / `monthly.yml` lack concurrency alignment with `daily.yml`, lack `Refresh committed state` & `already_published` guards, use Python `3.12` while `daily`/`ci` use `3.11`, and depend on 30-day GitHub artifact retention (which expires Day 1 before monthly runs on the 1st of a 31-day month).
   - `keepalive.yml` omits `pip install requests`, writes ASCII text over `state/secret_health_summary.json` (breaking JSON validation if pushed), and passes only 7 secrets.
   - Commit `c501625` broke `ci.yml` `Run Tests` because `tests/test_overnight_pacing.py` imports `yaml`, which is absent from `requirements.txt`.
